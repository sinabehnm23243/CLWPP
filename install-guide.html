مرحله ۱: ثبت‌نام در Cloudflare

۱ ورود به Cloudflare

به dash.cloudflare.com بروید. اگر اکانت ندارید، با ایمیل ثبت‌نام کنید (رایگان).

داشبورد اصلی Cloudflare پس از ورود

مرحله ۲: ایجاد KV Namespaces

۲ ایجاد KV برای کاربران و آمار

به Storage & Databases → KV بروید و دو namespace بسازید:

  • users — برای ذخیره اطلاعات کاربران
  • stats — برای ذخیره آمار مصرف
صفحه ایجاد KV Namespace
نکته: ID هر KV را ذخیره کنید — در مرحله ۵ نیاز خواهید داشت.

مرحله ۳: ایجاد Worker جدید

۳ ساخت Worker

به Workers & Pages → Create بروید:

لیست Workers و دکمه Create
  • نام Worker را cf-proxy-pro بگذارید
  • روی Deploy کلیک کنید
  • سپس روی Edit code کلیک کنید

مرحله ۴: کپی کد Worker

۴ اضافه کردن کد

در ادیتور کد، دو فایل ایجاد کنید:

فایل ۱: _worker.js

محتوای فایل _worker.js از پوشه cloudflare-proxy-worker-pro را کپی و در اینجا جایگزین کنید.

فایل ۲: blake3.js

در همان ادیتور، یک فایل جدید با نام blake3.js ایجاد کنید و محتوای فایل blake3.js را در آن کپی کنید.

ادیتور کد Cloudflare Workers — دو فایل را در پنل چپ ببینید
هشدار: حتماً هر دو فایل را اضافه کنید. بدون blake3.js، Worker در زمان درخواست SS 2022 خطا می‌دهد.

مرحله ۵: افزودن Bindings

۵ اتصال KV و Durable Object

به Settings → Bindings بروید و سه binding اضافه کنید:

Binding ۱: KV Namespace

  • Variable name: USERS_KV
  • KV namespace: users

Binding ۲: KV Namespace

  • Variable name: STATS_KV
  • KV namespace: stats

Binding ۳: Durable Object

  • Variable name: XHTTP_SESSION
  • Durable Object class: XhttpSession
صفحه Bindings در تنظیمات Worker
موفقیت: پس از افزودن هر سه binding، صفحه را ذخیره کنید.

مرحله ۶: افزودن متغیرهای محیطی

۶ تنظیم متغیرها

در همان صفحه Settings → Variables، این متغیرها را اضافه کنید:

متغیرهای لازم:

نام متغیر مقدار نمونه نوع
UUIDd342d11e-d424-...Text
TROJAN_PASSWORDرمز قویSecret
SS_PASSWORDرمز قوی متفاوتSecret
SS2022_PASSWORDopenssl rand -base64 32Secret
ADMIN_TOKENopenssl rand -hex 32Secret

تولید مقادیر با OpenSSL:

$ openssl rand -base64 32     # برای SS2022_PASSWORD
$ openssl rand -hex 32        # برای ADMIN_TOKEN
$ uuidgen                     # برای UUID (در لینوکس)
$ python -c "import uuid; print(uuid.uuid4())"  # برای UUID

مرحله ۷: Deploy نهایی

۷ ذخیره و Deploy

به ادیتور کد برگردید و روی دکمه Save and Deploy در بالا راست کلیک کنید.

پس از Deploy موفق: Worker شما روی آدرس زیر در دسترس خواهد بود:
https://cf-proxy-pro.<your-username>.workers.dev/
دکمه Deploy در بالای ادیتور

مرحله ۸: تست Worker

۸ تست صفحه راهنما

آدرس Worker را در مرورگر باز کنید:

https://cf-proxy-pro.<your-username>.workers.dev/

باید صفحه‌ای با ۵ کانفیگ، ساب‌لینک، پنل مدیریت و بخش Clean IP ببینید.

تست ساب‌لینک:

https://cf-proxy-pro.<your-username>.workers.dev/sub

باید یک رشته Base64 طولانی برگرداند که شامل هر ۵ کانفیگ است.

تست در کلاینت:

  1. یکی از کانفیگ‌ها را کپی کنید (VLESS پیشنهادی)
  2. در کلاینت (v2rayN، NekoBox، Streisand، V2RayNG) وارد کنید
  3. اتصال را تست کنید

مرحله ۹: تنظیم دامنه اختصاصی (اختیاری)

۹ استفاده از دامنه خودتان

اگر workers.dev فیلتر است، یک دامنه اختصاصی به Worker اختصاص دهید:

  1. در Cloudflare یک دامنه ثبت کنید (یا از دامنه‌های رایگان eu.org استفاده کنید)
  2. به Workers → cf-proxy-pro → Triggers → Custom Domains بروید
  3. یک ساب‌دامنه مثل proxy.example.com اضافه کنید
  4. کانفیگ کلاینت را با دامنه جدید به‌روزرسانی کنید
مزیت: دامنه اختصاصی معمولاً فیلتر نیست و سرعت بهتری دارد.

مرحله ۱۰: استفاده از بخش Clean IP

۱۰ جستجوی IP تمیز

به آدرس زیر بروید:

https://cf-proxy-pro.<your-username>.workers.dev/cleanip

امکانات بخش Clean IP:

  • 🎬 تست Netflix (آیا IP توسط Netflix بلاک شده؟)
  • 🤖 تست ChatGPT/OpenAI (آیا IP از OpenAI محروم است؟)
  • 🏰 تست Disney+
  • 📺 تست YouTube
  • 🎵 تست Spotify
  • 🎵 تست TikTok
  • ☁️ تست Cloudflare (وضعیت اتصال + لوکیشن)

مرحله ۱۱: پنل مدیریت کاربران

۱۱ مدیریت کاربران

به آدرس زیر بروید (با توکن تنظیم‌شده در متغیر ADMIN_TOKEN):

https://cf-proxy-pro.<your-username>.workers.dev/admin?token=YOUR_ADMIN_TOKEN

امکانات پنل:

  • ➕ افزودن کاربر جدید (UUID، نام، رمز Trojan، رمز SS)
  • 📋 لیست کاربران فعلی
  • 📊 مشاهده آمار مصرف هر کاربر (آپلود/دانلود/کل به MB)
  • 🗑️ حذف کاربران
  • ✓/✗ فعال/غیرفعال کردن کاربران
نمونه‌ای از پنل مدیریت

نکات نهایی

✅ نصب موفق بود!

اگر همه مراحل را درست انجام داده باشید، Worker شما آماده استفاده است. این موارد را به خاطر بسپارید:

  • سقف رایگان Workers: ۱۰۰٬۰۰۰ درخواست در روز
  • سقف رایگان KV: ۱۰۰٬۰۰۰ reads و ۱٬۰۰۰ writes در روز
  • سقف رایگان Durable Objects: ۱۰۰٬۰۰۰ requests در روز
  • ADMIN_TOKEN را قتی نگه دارید — دسترسی کامل به پنل دارد
  • هر چند وقت یک‌بار UUID و رمزها را تغییر دهید

⚠️ هشدارهای امنیتی

  • هرگز ADMIN_TOKEN را در کد Hard-code نکنید — در Variables با نوع Secret ذخیره کنید
  • SS2022_PASSWORD باید base64 یک کلید ۳۲ بایتی باشد (نه یک رمز متنی)
  • اگر Worker به‌طور عمومی قابل دسترسی است، rate limiting را فعال کنید
  • برای محیط production، CORS و IP allowlist را اضافه کنید

راهنمای Troubleshooting

مشکل: Worker خطای 500 می‌دهد

احتمالاً یکی از متغیرهای محیطی تنظیم نشده. به Settings → Variables بروید و همه متغیرهای لازم را بررسی کنید.

مشکل: کلاینت وصل نمی‌شود

  1. صفحه راهنما / را باز کنید — کانفیگ‌های آماده را کپی کنید
  2. ساب‌لینک /sub را در کلاینت اضافه کنید
  3. اگر workers.dev فیلتر است، از دامنه اختصاصی استفاده کنید
  4. پروتکل XHTTP را امتحان کنید (وقتی WS فیلتر است)

مشکل: پنل مدیریت باز نمی‌شود

بررسی کنید که ADMIN_TOKEN در URL با مقدار تنظیم‌شده در Variables مطابقت داشته باشد.

مشکل: آمار مصرف صفر است

بررسی کنید که STATS_KV به‌درستی به KV namespace متصل شده باشد. در Bindings بررسی کنید.
